第八章 增长决策 Agent：让数据自己说话

本章小节
  • 8.1 增长决策 Agent 的项目拆解：五维分析
  • 8.2 渠道增长分析器：漏斗效率、用户质量与边际成本
  • 8.3 转化结构分析器与用户资产分析器
  • 8.4 专项 Agent 体系：诊断、预测与分层
  • 8.5 增长洞察日报与机会排行榜

增长团队里最忙的人，往往不是投手，也不是主播，而是那个既懂业务又懂数据的分析师。周一早上，投手问“昨天成本为什么涨了”，分析师花两个小时取数、对齐口径、画图，结论是“大盘涨了，我们的涨幅低于大盘”。中午，直播负责人问“上周哪个年级的转化最好”，分析师又花一个小时，发现三个系统的年级字段不一致，只能手工映射。下午，老板问“这个月能不能完成收入目标”，分析师把五张表拼在一起，算出三种不同的结果，最后选了一个最保守的报上去。

一天下来，分析师做了三件事：取数、对账、解释。真正有价值的分析——为什么涨、该怎么调、下个月会怎样——几乎没有时间做。业务方的感受则是“数据支持太慢”，于是越来越多的问题改成凭经验拍板。分析师越忙，业务越不信数据；业务越不信数据，越少提需求；分析师越闲，越远离业务。这个循环在很多在线教育机构里反复上演。

增长决策 Agent 要解决的，就是把这个循环打断。它把高频、重复、口径固定的分析任务接管过来，让业务在几分钟内得到答案，让分析师把时间花在复杂的归因和策略上。Agent 不是一个大而全的聊天机器人，而是一组按项目拆解的分析器：渠道分析器、转化分析器、用户资产分析器、专项预测器。每个分析器有明确的输入、口径、输出和动作建议，能独立运行，也能组合成一条诊断链。

8.1 增长决策 Agent 的项目拆解：五维分析

（一）先拆项目，再谈智能

“做一个增长决策 Agent”是一个太大的命题。太大的命题通常落不了地，因为它没有明确的输入、输出和验收标准。可行的做法是把它拆成项目，每个项目回答一类问题，服务一类使用者，产出一种动作。

拆项目的标准有三个。可验证，Agent 给出的结论能被数据或业务结果检验，而不是一段无法证伪的分析。可归因，结论能指向具体原因，而不是“整体表现不佳”。可执行，结论能翻译成某个团队今天能做的动作，而不是“建议持续优化”。

按这三个标准，增长分析可以拆成五个维度：渠道、转化、用户、内容、竞品。渠道回答“用户从哪里来、成本是否可持续”，转化回答“用户在哪一步流失、为什么”，用户回答“谁值钱、谁要流失、谁该召回”，内容回答“什么选题、什么素材、什么话术有效”，竞品回答“相对位置有没有变化、对方的打法是否值得借鉴”。

五个维度不是并列的报表，而是一条诊断链。渠道出问题，先看转化；转化出问题，先看用户结构；用户出问题，先看内容和触达；内容和触达都正常，再看竞品是否改变了市场环境。诊断链的顺序很重要，它决定了团队从哪里开始查，而不是一上来就全盘分析。

（二）每个维度的核心问题与输出

渠道维度要回答效率、质量与边际成本三个问题。哪个渠道效率最高，哪个渠道用户质量最好，哪个渠道加预算之后成本仍然可控，这三个答案决定预算怎么分。输出是一张渠道评分卡，包含规模、转化率、用户质量、成本、弹性五个维度，以及预算调整建议。

转化维度先要找到漏斗断得最厉害的一级，再解释断的原因。输出是一张转化结构图，按年级、产品、时段、人群拆开，标出与基线的差异，以及最值得优化的三个环节。

用户维度看的是四个池子的容量与迁移是否健康，哪些用户有流失风险，哪些流失用户值得召回。输出是一张资产健康表，包含池子容量、迁移率、预警名单、召回优先级。

内容维度要区分哪些内容带来了高质量用户，哪些只是带来了播放。输出是一张内容效果表，按选题、开头、证据、行动分类，标注播放、完播、加微、转化的组合表现。

竞品维度关注对方打法的变化，以及变化对自己意味着什么。输出是一张竞品变化表，记录价格、货盘、时长、话术、投放痕迹的变化，以及对应的应对建议。

五个输出都不求全，只求能被用起来。一张渠道评分卡如果没人看，不如不做；一张转化结构图如果指不出动作，不如不做。Agent 的价值不在于分析得多全面，而在于分析得能被执行。

（三）项目制的组织方式

Agent 项目需要三类角色：业务负责人、数据负责人、产品负责人。业务负责人定义问题和验收标准，数据负责人保证口径和数据质量，产品负责人把分析变成可用的界面和流程。三类角色缺一个，项目就会偏：只有业务，Agent 会变成拍脑袋的工具；只有数据，Agent 会变成报表生成器；只有产品，Agent 会变成好看的摆设。

项目节奏可以按“两周一个小闭环”推进。第一周定义问题和口径，第二周做出第一版分析，第三周在真实场景试用，第四周根据反馈迭代。一个小闭环结束，再进入下一个维度。不要一次做五个维度，五个维度同时做，每个都做不深。

验收标准要提前写。比如渠道分析器的验收标准可以是：能在十分钟内回答“昨天哪个渠道的成本异常”，能给出至少一条可执行的预算调整建议，建议执行后一周内能看到成本变化。标准写得具体，验收才不会变成“看起来不错”。

（四）从单维到交叉

单维分析能解决大部分日常问题，但真正的洞察往往来自交叉。渠道加年级，能看出某个渠道在某个年级的效率特别高；转化加内容，能看出某类内容带来的用户在试听环节更容易转化；用户加竞品，能看出流失用户是否流向了某个特定竞品。

交叉分析不能一上来就做。单维的口径没稳定，交叉只会放大错误。合理的顺序是先把五个单维做稳，再做两两交叉，最后做组合诊断。每增加一层交叉，数据要求就高一截，团队要判断自己是否准备好了。

交叉分析的输出要克制。一次只给三条结论，每条结论带一个动作。交叉分析很容易产出大量“有趣但无用”的发现，比如“周三下午来的用户在雨天转化率更高”。这种发现没有执行价值，只会分散注意力。

（五）Agent 不替代分析师

Agent 接管的是重复分析，不是全部分析。分析师的价值在于提出好问题、设计归因、解释异常、判断策略。Agent 可以把“昨天成本为什么涨”拆成十个可能原因，逐个检查数据，但最终判断“是竞争加剧还是我们素材老化”，仍需要分析师的业务直觉。

分析师还要负责校准 Agent。Agent 的结论准不准，需要人回测；Agent 的口径对不对，需要人审核；Agent 的建议有没有效，需要人跟踪。没有分析师校准，Agent 会在错误的方向上越跑越远。

分析师更要负责“问对问题”。Agent 擅长回答已经被定义的问题，不擅长发现未被定义的问题。分析师看到某个异常，提出一个新假设，再让 Agent 去验证，这种协作比让 Agent 自由发挥更有效。

8.2 渠道增长分析器：漏斗效率、用户质量与边际成本

（一）漏斗效率：逐级转化，而不是只看 CPA

渠道分析最常见的指标是 CPA，单条线索成本或单次成交成本。CPA 简单直观，但它把所有环节压缩成一个数，掩盖了结构差异。两个渠道 CPA 相同，一个点击便宜但转化差，一个点击贵但转化好，优化方向完全不同。

漏斗效率要把 CPA 拆开。曝光到点击的点击率，点击到进入的进入率，进入到留资的留资率，留资到加微的加微率，加微到试听的试听率，试听到报名的报名率。每一级都有成本和时间，每一级的流失原因不同。拆开之后，团队才知道该优化素材、落地页、承接话术，还是产品本身。

逐级转化要和基线比。基线可以是自己的历史，也可以是同类渠道的公开水平。比基线低得最多的一级，就是最值得优化的环节。优化要有优先级，不要六个环节一起改，改完不知道哪个有效。

漏斗还要看时间。用户从点击到报名，可能经历几天甚至几周。只看当天的转化，会低估长决策周期的渠道；只看最终转化，会忽略中间环节的流失。分析时要设定归因窗口，并保持窗口一致，否则渠道之间的比较没有意义。

（二）用户质量：首购之后的三个指标

渠道带来的用户，质量差异很大。有的渠道带来的是“领完资料就走”的用户，有的渠道带来的是“试听后就报名”的用户。只看首购成本，会偏向低价渠道；只看首购量，会偏向泛流量渠道。质量要看首购之后的三个指标：三十日复购率、九十日续费率、退课率。

三十日复购率反映产品匹配度。用户买了第一次，三十天内会不会买第二次，说明他是否真的需要这类产品。九十日续费率反映长期价值。用户是否愿意继续付费，说明产品是否持续有效。退课率反映承诺与交付的差距。退课率高，说明前端卖得过度，后端交付不足。

三个指标要按渠道拆。一个渠道首购成本低、复购率高、退课率低，是优质渠道；一个渠道首购成本低、复购率低、退课率高，是“便宜但有毒”的渠道。后者的长期成本，往往高于前者。

质量还要看用户结构。同一个渠道，带来的用户可能集中在某个年级、某个城市、某类需求。结构不同，运营成本不同。一个渠道带来大量低年级用户，需要长期培育；一个渠道带来大量毕业年级用户，短期收入高但生命周期短。渠道评价要结合结构，不能只看平均数。

（三）边际成本：平均成本会骗人

平均 CPA 是总成本除以总转化，它假设每一块钱的效率相同。现实中，预算增加时，效率通常会下降：最先买到的量是最便宜的量，越往后越贵。只看平均成本，会误判“还能不能加预算”。

边际成本要看增量。预算从一万加到两万，转化从一百加到一百七十，边际成本是两万减一万，除以一百七十减一百，得到每增加一个转化要多花多少钱。边际成本低于可承受的获客成本，就还有加预算的空间；边际成本高于可承受的成本，加预算就会亏。

边际成本会随着规模变化。小预算时边际成本低，中等预算时边际成本上升，接近饱和时边际成本急剧上升。找到“边际成本等于可承受成本”的那个点，就是渠道的经济上限。超过这个点，规模越大，亏损越多。

边际成本还要看渠道之间的相互影响。在 A 渠道加预算，可能会抢走 B 渠道的量，也可能带来 B 渠道拿不到的新用户。渠道之间不是独立的，预算分配要考虑组合效应。分析时要看“总预算增加”的边际成本，而不只是单渠道的边际成本。

（四）渠道评分卡与预算建议

把漏斗效率、用户质量、边际成本放在一起，可以做成一张渠道评分卡。评分卡包含五个维度：规模，能带来多少量；效率，逐级转化率；质量，复购、续费、退课；成本，CPA 与边际成本；弹性，加预算后的效率变化。每个维度打分，加权汇总，得到渠道的综合评分。

评分不是目的，预算建议才是。高分渠道可以加预算，但要监控边际成本；中分渠道可以优化漏斗，找到最弱的一环；低分渠道要评估是否继续，如果长期低效且无改善空间，应该果断收缩。预算分配不是平均主义，也不是唯 ROI，而是综合评分加战略价值的判断。

预算建议要写清楚假设。比如“建议 A 渠道加预算两万，假设边际成本仍低于目标成本，预计新增转化三十个”，执行后回看假设是否成立。假设写清楚，复盘才有依据；假设不写，建议就成了拍脑袋。

评分卡要定期更新。渠道的效率会随竞争、季节、平台规则变化，上个月的高分渠道，这个月可能变成低分。更新频率可以是每周一次小更新，每月一次大复盘。更新不是为了排名，而是为了调整资源。

（五）渠道分析的四个陷阱

第一个陷阱是归因窗口不一致。A 渠道用一天归因，B 渠道用七天归因，B 渠道会显得更好，因为它把后续的转化都算进来了。归因窗口必须统一，或者至少在同一张表里标注清楚。

第二个陷阱是重复计数。同一个用户从多个渠道进入，可能在每个渠道都被算一次转化。重复计数会高估总转化，低估单渠道成本。要去重，用统一的用户标识，把转化归给最后一次有效触达或第一次有效触达，规则要固定。

第三个陷阱是把自然流量算成付费。用户看了广告没有点，后来自己搜索进来，转化被算作自然流量，广告的价值被低估。反之，把自然流量算成付费，广告的价值被高估。要用对照实验或平台归因工具，区分增量与自然。

第四个陷阱是只看短期。渠道带来的用户，可能在三个月后才续费，只看首购会低估长期价值。分析要把时间拉长，至少覆盖一个续费周期。短期数据用于优化，长期数据用于决策。

8.3 转化结构分析器与用户资产分析器

（一）转化结构：先拆开，再找差异

转化率是一个平均数，平均数会掩盖结构。整体试听转化率百分之三十，拆到年级，可能一年级是百分之四十五，六年级是百分之十五；拆到产品，可能大班是百分之三十五，小班是百分之二十；拆到时段，可能周末是百分之四十，工作日晚上是百分之十八。结构差异找到，优化才有方向。

拆分的维度不要太多。一次拆一到两个维度，最多三个。拆得太多，每个格子样本太小，结论不可靠。常见的拆法是年级加产品、渠道加年级、时段加产品。先看哪个维度差异最大，再在这个维度里继续拆。

差异要找“异常高”和“异常低”。异常高的组合，可能是被忽略的机会，比如某个低流量年级的转化率特别高，值得加大投入；异常低的组合，可能是隐藏的问题，比如某个产品的退款率特别高，需要检查交付。异常值比平均值更有信息量。

转化结构还要看时间趋势。某个年级的转化率这个月突然下降，可能是政策变化、竞品动作、产品调整。趋势变化要结合事件标注，否则无法归因。

（二）转化分析器的输出：三个环节、三个动作

转化分析器的输出不求多，只求准。每次分析给出三个最值得优化的环节，每个环节配一个动作。比如“六年级试听到报名的转化率低于基线十个百分点，建议调整试听课的难度，让它更接近正式课”；“工作日晚间的加微率低，建议把欢迎语从课程介绍改为资料领取”；“小班的退课率高，建议在开课前增加一次学习规划沟通”。

三个环节的选择要有依据。优先选影响最大的环节，比如流失最多的那一级；其次选最容易改的环节，比如话术、欢迎语、表单字段；最后选改动成本最低的环节，比如素材替换、排期调整。三个标准结合，才能既有效又可行。

动作要能被验证。每个动作上线后，设定一个观察周期和判断标准。比如“调整试听课难度后，两周内试听到报名率提升三个百分点”，达标就保留，不达标就回滚。没有验证，动作会变成一次性尝试，无法积累。

分析器还要能解释“为什么”。同样是试听转化率低，原因可能是难度不匹配、老师不匹配、时间不合适、价格超出预期。分析器要给出候选原因和对应的证据，让人快速判断，而不是给一个笼统的“转化率低”。

（三）用户资产分析器：容量、迁移、预警

用户资产分析器的第一项输出是容量。四个池子各有多少人，这个月流入多少、流出多少、净增多少。容量变化能看出经营的早期信号：新潜池暴涨，说明拉新猛但承接不足；高价值池萎缩，说明底盘在漏；流失高潜池扩大，说明防流失失效。

第二项输出是迁移。新潜到首购的迁移率、首购到高价值的迁移率、高价值到流失的迁移率、流失到召回的迁移率。迁移率要和上月、去年同月对比，看趋势。迁移率下降，说明关键动作失效；迁移率上升，说明动作有效，可以复制。

第三项输出是预警名单。哪些用户出现流失信号，信号是什么，建议什么动作，由谁跟进。名单要按优先级排序，高价值高风险排最前。名单不能太长，超过一线处理能力，就会被搁置。

三项输出要联动。容量变化解释迁移，迁移解释名单，名单回到容量。比如高价值池萎缩，迁移显示高价值到流失的迁移率上升，名单显示一批高价值用户出勤下降，动作就是干预这批用户的出勤问题。联动起来，分析才有因果链。

（四）两个分析器的联动

转化分析器和资产分析器要一起看。转化率下降，可能是流量结构变化，也可能是承接能力下降；资产流失增加，可能是转化环节把不合适的人拉进来，也可能是交付环节没接住。单看一个分析器，容易归错因。

联动的方法是对齐时间轴。把转化率、池子容量、迁移率、预警数量按周画在同一张图上，看它们的变化是否同步。转化率下降两周后，流失预警增加，说明前端拉来的用户质量有问题；流失预警增加两周后，转化率下降，说明后端交付问题影响了口碑和转介绍。

联动还要对齐人群。转化分析按年级、渠道拆，资产分析也按同样的维度拆，才能对上。维度不一致，分析会变成两张皮。统一维度是联动的前提，也是数据治理的一部分。

联动的结论要落到动作。比如“六年级试听转化下降，同时六年级高价值池流失增加，说明试听课与正式课的落差在伤害信任，建议统一试听课与正式课的老师与难度”。这种结论比单维分析更有价值，因为它把前端和后端连起来了。

（五）分析器的边界

分析器能告诉你“哪里断了”，不能告诉你“为什么断”。原因需要人补充，尤其是涉及情绪、关系、口碑的原因。分析器能给出候选原因，但不能替人做最终判断。

分析器能给出建议，不能替人做决策。建议要经过业务判断，尤其是涉及价格、承诺、人员调整的建议。机器不懂品牌，也不懂人心。

分析器能处理结构化数据，不能处理非结构化信息。家长的抱怨、老师的观察、社群的讨论，这些信息不在报表里，需要人收集、整理、输入。分析器可以辅助分析文本，但不能替代一线的感知。

8.4 专项 Agent 体系：诊断、预测与分层

（一）增长诊断 Agent：每周做一次体检

增长诊断 Agent 的任务，不是回答某个具体问题，而是每周给业务做一次体检。体检的内容包括五个维度：流量是否健康、转化是否正常、资产是否增厚、内容是否有效、竞品是否变化。每个维度设几个关键指标，和基线对比，标出异常。

体检的价值在于“早发现”。很多问题在爆发之前，已经有指标变化：加微率连续两周下滑、某个年级的退课率缓慢上升、某个渠道的边际成本逼近上限。单看一天的数据，这些变化不明显；按周对比，趋势就会显形。诊断 Agent 把趋势算出来，提醒团队在问题变大之前处理。

异常要分级。红色异常是已经影响收入的问题，比如成交额连续下滑、退课率突然翻倍，需要当天处理；黄色异常是可能影响未来收入的问题，比如加微率下滑、试听预约减少，需要本周处理；蓝色异常是值得关注但暂不紧急的问题，比如某个内容类型的完播率下降，进入观察。

诊断的输出要短。每周一页，写三到五条异常，每条附一个可能原因、一个建议动作、一个责任人。不要写成二十页的报告，没人看。诊断不是学术研究，它是一张待办清单。

诊断 Agent 还要能做“归因链”。发现成交额下滑，自动往下拆：是流量少了，还是转化低了，还是客单降了；如果是转化低，再拆是哪个年级、哪个产品、哪个环节；如果是某个环节，再拆是素材、落地页、话术还是承接。拆到能执行的那一层，诊断才有用。

（二）收入预测 Agent：给区间，不给点

收入预测是管理层最关心的分析，也是最容易出错的分析。错误通常来自两个地方：把预测当成承诺，把点估计当成确定值。收入受太多因素影响：新增、续费、退课、客单价、季节性、政策、竞争。任何一个因素变化，预测都会偏。

可行的做法是给区间，不给点。预测下个月收入在八百万到九百五十万之间，比预测“九百万”更有信息量。区间的宽度反映不确定性，不确定性大时区间宽，确定性高时区间窄。管理层根据区间做资源安排，而不是把区间中点当成目标。

预测要拆成分。收入等于在读存量乘以续费率，加上新增用户乘以转化率乘以客单价，减去退课与退款。每个分量的预测单独做，再合成。分量预测可以让对应团队负责：续费率由教学和运营负责，新增由投放和内容负责，退课由交付负责。责任清楚，预测才有依据。

预测要滚动更新。每周更新一次，把最新的实际数据替换进模型，调整后续预测。滚动预测的好处是能快速反映变化，而不是等到月底才发现偏差。更新时要记录“为什么调整”，是新增低于预期，还是续费高于预期，调整原因要能追溯。

预测还要做情景分析。基准情景是当前趋势延续；乐观情景是某个关键动作生效，比如续费率提升、某个渠道放量；悲观情景是某个风险发生，比如政策收紧、竞争加剧。三个情景给管理层看，帮助其做预案。只给一个情景，会让管理层误以为未来只有一种可能。

（三）流失预测 Agent：提前期比准确率更重要

流失预测的目标，是在用户真正流失之前识别出来，给运营留出干预时间。预测的提前期，比预测的准确率更重要。提前一周预测出来，运营只能做紧急挽回；提前一个月预测出来，运营可以做诊断、调整、沟通，挽回成功率会高很多。

提前期的设定，要看业务节奏。续费前一个月是关键窗口，超过一个月，用户可以已经被竞品接触；少于两周，干预手段有限。合理的提前期是四到六周，给运营足够的动作空间。

特征的选择，要兼顾预测力和可解释性。出勤率、作业提交率、课堂互动、家长消息回复、投诉记录、成绩变化、老师评价，都是有效特征。特征不需要多，五到十个就够，太多会过拟合。

准确率和召回率要权衡。准确率高，意味着预测为高风险的用户里，真正流失的比例高，运营不会浪费太多时间；召回率高，意味着真正会流失的用户里，被预测出来的比例高，遗漏少。在线教育的干预资源有限，通常优先保证准确率，避免运营被大量误报拖垮；同时保留一个人工复核环节，处理边界案例。

预测结果要变成干预清单：每个高风险用户配一个可能原因、一个建议动作、一个责任人和截止时间。原因可以来自特征：出勤下降，可能是学习跟不上；互动减少，可能是家长不满意；投诉记录，可能是服务问题。动作要具体，比如“老师本周内做一次电话沟通，了解学习困难”“邀请参加一次家长会”“提供一次免费诊断”。

预测要回测。每个月看一次：预测为高风险的用户里，实际流失多少；实际流失的用户里，预测出来多少；干预过的用户，流失率是否低于未干预的对照组。回测结果用来调特征、调阈值、调干预策略。没有回测，预测只是猜测。

（四）成交预测 Agent：排序，不是判决

成交预测的目标，是给线索排序，让销售先跟最可能成交的人。它不是给用户判死刑。排序的价值在于效率，判决的风险在于错杀。

预测的特征包括：线索来源、年级、咨询内容、响应速度、互动频率、资料使用、试听完成、价格敏感度、历史购买。特征要能反映真实意向，而不是反映“销售跟得勤”。如果一个特征是因为销售跟得勤才产生的，它会让模型偏向已经被跟过的用户，忽略未被跟过的高潜用户。

输出可以是分数，也可以是分层。分数用于排序，分层用于分配。A 级当天跟，B 级三天内跟，C 级进入培育。分层标准要定期校准，避免所有线索都被打成 A 级，或者所有线索都被打成 C 级。

成交预测要允许人工调整。销售最了解用户，模型给出排序，销售可以根据对话情况调整优先级。调整要记录，用于优化模型。如果销售经常把 C 级跟成 A 级并且成交，说明模型漏掉了某些信号；如果销售经常把 A 级降成 C 级并且没成交，说明模型高估了某些信号。

预测不能替代服务。即使用户成交概率低，也应该得到基本的响应和尊重。把资源向高概率用户倾斜是经营选择，但不能因此怠慢其他用户。

（五）四个 Agent 的共性

四个 Agent 看起来做的是不同的事，底层逻辑相同：定义问题、选择特征、建立基线、输出概率或区间、给出动作、回测效果。任何一个环节缺失，Agent 都会退化成“看起来智能的报表”。

共性还包括“可解释”。每个预测结果都要能说明“为什么”，是哪些特征导致的，特征的变化趋势如何。不可解释的预测，业务不敢用。

共性还包括“可干预”。预测的目的不是知道，而是行动。如果一个预测结果没有对应的动作，它就不应该出现在日报里。预测越准，越要克制，只把能干预的部分推给一线。

共性还包括“可回滚”。任何自动化的建议，都要有回滚机制。预测错了，动作可以撤回；动作造成了负面影响，可以及时止损。没有回滚，团队不敢用自动化。

8.5 增长洞察日报与机会排行榜

（一）日报的价值在“今天做什么”

多数增长日报的问题是“信息过载”。二十个指标、十张图、五段分析，看完不知道今天该做什么。日报的目的不是记录昨天，而是指导今天。它应该回答三个问题：昨天发生了什么异常，可能的原因是什么，今天谁该做什么。

日报的结构可以固定为四段。第一段是一句话结论，比如“昨日成交低于目标一成，主要受六年级转化下滑影响”。第二段是三条关键变化，每条带数据和时间。第三段是原因假设，标注置信度。第四段是今日动作，写明责任人、截止时间、验收标准。

日报要在早上八点前推送，晚了就变成“事后阅读”。推送渠道要固定，企业微信、飞书、邮件都行，但不要同时在三个地方发，信息会分散。

日报要能点开细节。一句话结论背后，要能链接到详细分析；一个异常指标，要能点开看分渠道、分年级、分时段。日报是入口，不是全部。

日报要有反馈机制。收到日报的人可以标记“已知”“需讨论”“误报”，这些反馈用来优化日报的规则。长期误报的规则要下线，长期被忽略的指标要删除。

（二）机会排行榜：把分析变成优先级

机会排行榜是 Agent 最有价值的产品形态之一。它把分析结果按“预期增量价值除以执行成本”排序，告诉团队“如果今天只做三件事，做哪三件”。

机会的来源包括：渠道预算调整、转化环节优化、高潜名单跟进、流失用户召回、内容选题调整、竞品应对。每个机会都要估算预期增量、执行成本、所需资源、风险。估算不需要精确，但要有依据，比如历史同类动作的提升幅度、当前环节的差距、可触达的用户量。

排行榜要分类。短期机会是几天内能执行、见效快的，比如预算调整、名单跟进；中期机会是几周内能完成、需要协作的，比如落地页改版、话术更新；长期机会是几个月才能见效的，比如产品升级、渠道建设。三类机会的比例要平衡，只做短期会透支，只做长期会失控。

排行榜要能下钻。点开一个机会，能看到数据依据、执行方案、责任人、预期效果、风险提示。机会不是一句“建议加大投放”，而是一个可执行的项目。

排行榜要每周更新。机会有时效，上周的机会这周可能已经消失。更新时保留历史记录，看哪些机会被采纳、哪些被忽略、采纳的效果如何。历史记录能校准估算，让下一次排序更准。

（三）让 Agent 成为决策依赖

Agent 要成为决策依赖，靠的不是功能多，而是建议准。一个建议被采纳、执行、验证有效，团队下一次就会更愿意听；连续几次建议无效，团队就会关掉通知。信任是一点点建立的，也是一次次消耗的。

建立信任的方法，是先做“低风险、高确定性”的建议。比如“这个渠道的边际成本已经超过上限，建议停止加预算”，这种建议容易验证，执行后很快能看到结果。先在小事上建立信任，再逐步进入复杂决策。

信任还需要“透明”。Agent 给出建议时，要说明依据、假设、可能的偏差。团队知道建议是怎么来的，才敢用；不知道，就只能凭感觉信或不信。

信任更需要“边界”。Agent 不应该给出涉及合规、品牌、人事的建议，也不应该替人做价值判断。它可以说“这个素材的点击率低”，不能说“这个老师不行”；它可以说“这个渠道的成本高”，不能说“这个渠道应该关掉，负责人应该换”。边界清楚，团队才敢长期使用。

（四）避免“数据依赖”变成“数据迷信”

Agent 用得好，团队会形成数据依赖；用得不好，会变成数据迷信。数据迷信的表现是：只信数字，不信一线观察；只看报表，不去现场；只追指标，不管用户体验。

避免迷信的方法，是保留“反数据”的渠道。一线的反馈、用户的抱怨、老师的观察，要和数据一起进入决策。数据说转化率正常，但老师反映学生跟不上，就要查数据口径和交付质量。数据说某个渠道很好，但销售反映线索质量差，就要查线索的后续转化。

还要保留“人工判断”的空间。Agent 给出建议，人可以否决，但否决要记录理由。理由积累起来，会发现某些场景下人的判断比模型准，这些场景就应该保留人工决策。模型不是越全越好，它应该知道自己不适合做什么。

最终，Agent 的角色是“参谋”，不是“司令”。它提供信息、分析、建议，人做决策、承担责任。参谋越强，司令越轻松；但司令不能把责任交给参谋。在线教育的增长涉及孩子的学习、家长的信任、机构的品牌，这些责任只能由人来承担。
